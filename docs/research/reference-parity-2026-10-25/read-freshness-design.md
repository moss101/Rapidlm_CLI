# Read-before-write parity: integration constraints

The existing `context_engine::ReadSet` is scoped to a session and an agent, stores typed `ContextLocator` and `ContentHash` values, has bounded capacity, distinguishes unknown/fresh/stale, and invalidates paths after writes. A source search found no production caller that records `ReadObservation`; it currently contributes no protection to workspace tool edits. `WorkspaceTools::execute_read` and `execute_repo_read` read bounded source bytes. `execute_write` and `execute_patch` acquire shared per-path `WriteLocks`, then run formatting, shadow checks, and atomic replacement; the lock prevents cooperating writers from racing but does not bind a write to anything the model previously read.

A correct REF-015 implementation must attach this existing authority to the actual model-visible read results, share it across later turns of the same session and actor, and keep a child's identity and isolated view distinct from its parent's. A resumed session must either reconstruct only provably visible reads from durable evidence or conservatively require a fresh read; it must not invent one from the current disk contents. Compaction/visibility generation and redaction need explicit treatment so a file that was never shown cannot confer write authority.

For a successful text or image read, record a whole-file digest of the original bounded bytes, not the UTF-16-to-UTF-8 display text or a truncated output fragment. Before replacing an existing file, under the same path lock used by the writer, read and compare the current raw bytes with that actor's last visible digest; an unknown or stale digest is a handled refusal telling the model to re-read. A missing target remains a permitted new-file creation, but read/metadata errors must not be mistaken for absence. Recheck immediately before replacement after formatter and shadow work. After success invalidate the old read record and related evidence; the user-visible write receipt must continue to describe the final formatted bytes. Apply the same rule to both exact and fuzzy patches and all write branches.

The existing in-process lock cannot stop external editors that ignore it between the last comparison and rename. Any guarantee beyond that requires an OS/filesystem primitive or an explicitly documented residual race; do not represent an advisory lock as an atomic cross-process compare-and-swap. Preserve workspace confinement and the existing permission decision before doing filesystem work. Tests need independent actors/views, cross-turn sharing, resume fail-closed behavior, stale and unread files, actual raw-byte encodings, new-file creation, formatting/shadow branches, concurrent writes and change/evidence invalidation. This document is analysis, not completion of REF-015.

## Approval continuation finding

The interactive continuation (`interactive.rs` `continuation_turn_inner`) builds a new `ExecTools` before executing the approved call. The original tool instance and its read authority are gone, so an approved edit of an existing file currently fails closed even if the model read it earlier in the suspended turn. The suspended exchange history is available, but the display result by itself is not proof of the original raw-byte fingerprint or actual model delivery and must not be used to reconstruct an authority by hashing the current file.

The kernel submits a new turn when resuming, so its current turn ID cannot identify the suspended run. The implementation instead retains the original in-memory authority under the session and unique approval token, verifies the canonical view on retrieval, and consumes the entry when that approval resumes. A new turn, fork, changed view, unmatched approval token, process restart, or lost registry must start without authority. Ensure cancelled/completed turns clear entries, repeated approval suspensions retain the same entry, and actor/subagent isolation remains explicit. This only carries reads already confirmed by the original model step; it does not authorize reads from the persisted transcript or silently grant prior-turn history. Verify the actual read -> edit request -> approve -> resumed write path, stale external edits while waiting, repeated approvals, restart fail-closed behavior, and a later independent turn. ACP and headless need separate ownership analysis rather than assuming the interactive registry applies to them.

## Model-history trimming

The runtime now reports a model-visible history suffix after every successful request, using an empty slice if the backing cannot attest delivery. The workspace authority keeps a bounded set of call/tool/argument/result fingerprints and raw-byte read tickets across the same live approval continuation. It reconciles visibility against each delivered suffix: matching results can be visible, missing results cannot, and a write or generation change prevents an old ticket from granting authority again. When proof capacity is exhausted, an older proof is evicted and its authority fails closed. Structured-output and goal lifecycle wrappers forward these observations to their underlying tools.

Focused tests exercise a dropped read, an exact result appearing again, a fresh read inside a trimmed suffix, writes invalidating old tickets, multiple paths, an unattested request, and approval replay. REF-015 remains pending: cross-turn history, ACP and child isolation, process restart, and full integration and regression acceptance still require evidence.

## Shared writer invalidation (implementation awaiting verification)

The shared per-path lock registry now also retains bounded weak references to participating authorities. A successful replacement invalidates the canonical path for each live actor in the same view, so even an identical-byte write revokes earlier reads. Admission to a different or already-used lock group advances the joining authority generation, avoiding acceptance of observations made outside that group. Registry poisoning or capacity exhaustion fails writes closed. The focused actor-isolation test, existing write-guard regression and Rapid all-target clippy passed after the loader recovered; broader cross-turn, restart and adapter coverage remains pending. External writers that do not use this registry remain outside its guarantees.

## ACP and daemon approval continuations

An ACP serve holds one bounded suspended-read registry, and a daemon shares one across its client connections. Each initial turn, approval continuation and question recovery gets that same token/session/view-scoped registry. A restarted host starts with an empty registry; it does not recover a read fingerprint from current disk bytes or the transcript. ACP and daemon continuation assembly also retain the surface's permission-mode cell, including a mode change while an approval is pending. Scripted loopback integration tests exercise real ACP stdio and daemon socket flows for unchanged files and external changes; the daemon test also exercises reconnect and process restart. A shared host-scoped lock group invalidates read proofs across its own live sessions, including identical-byte writes. Independent processes and external writers do not share that group, so identical-byte writes outside it cannot be detected by the fingerprint alone. Cross-turn delivery, child/view isolation and final acceptance remain open.

## External file identity

Production reads capture regular-file metadata before reading and only stage the proof if that metadata is unchanged afterwards. Alongside the raw content digest, the committed proof retains the file length and modification time; on Unix it also retains device, inode and change time. The write guard compares that evidence before and after its bounded read immediately before replacement. This detects ordinary identical-byte replacement by another process and rejects a file that changed during staging. Filesystems can have coarse or mutable metadata, and an external writer can still race after the final check; this is not an atomic cross-process compare-and-swap. External in-place writes that leave all recorded metadata indistinguishable remain unproven.

## ACP process restart

The real ACP binary test `acp_restart_does_not_reconstruct_read_authority_from_session_history` reads an existing file, closes the host, loads the same session in a new process and attempts an auto-allowed write without another read. The tool fails and the original bytes remain. A read in the new process then permits a later edit in that same session. The test uses a loopback scripted model and a clean process exit; it does not establish behavior at every crash boundary or on other client surfaces. REF-015 remains pending overall acceptance.
