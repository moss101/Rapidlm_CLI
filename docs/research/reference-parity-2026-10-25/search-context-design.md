# Search context and stable pagination — REF-017

The pinned Kimi `packages/agent-core-v2/src/agent/tools/os/grep/grep.ts` exposes separately configurable before, after and symmetric context, as well as content, file and count output shapes. RapidLM supports those shapes with before/after context bounded at 20 lines. Overlapping or adjacent context ranges merge, output is ordered by path and line, and offset/head limits apply to rendered rows. Byte-limited pages advance only over delivered rows; long rows are explicitly marked for `repo_read`. Context expansion is refused for count and file modes.

Each grep hit carries a hash of the original file bytes. Context rendering rereads the file within the existing limits and refuses if the bytes no longer match, preventing one result from combining versions. Expanded rows are streamed rather than retained as an unbounded collection, and search cancellation and the two-second bound also apply during expansion.

The walker now distinguishes deliberate ignore/binary/symlink exclusions from traversal bounds and selected oversized text files. Search and glob report the latter as incomplete, including an empty glob result; I/O and invalid ignore data fail the operation. Ignore files are bounded while reading, overlong rules are refused rather than silently dropped, and non-ASCII patterns do not split UTF-8. Focused tests cover overlap, sorted multi-file pages, byte pagination, long-line readback, changed sources, ignored files, depth and size omissions, output modes, and the configured binary. The full context-engine regression passed all 319 tests; final workspace/platform acceptance remains separate under REF-027.
