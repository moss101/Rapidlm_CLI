## Measurement (goal §7: tokens and cost per verified success)

- **rapid**: `rapid exec --usage-file` writes the turn's measured
  consumption as JSON — total tokens, and the provider-reported split
  (input / cached-input / output; x.ai itemizes cached tokens). The
  OpenAI-compatible endpoint reports NO cost field, so rapid's cost is an
  **estimate**: the measured split priced at x.ai's published grok-4.6
  rates ($2.00 input / $0.50 cached input / $6.00 output per 1M tokens,
  [x.ai/api](https://x.ai/api), [docs.x.ai/developers/pricing](https://docs.x.ai/developers/pricing)),
  recorded in a separate `cost_estimate_usd_micros` field that never merges
  with measured cost. When the provider does not itemize the cached subset,
  all input is priced at the uncached rate (a stated upper bound).
- **grok CLI**: `--output-format json` returns the provider-reported
  `usage.total_tokens`, the token split, and `total_cost_usd_ticks` —
  measured cost, not an estimate.
- The report (`per_agent_usage` block in each results JSON) divides each
  agent's totals by ITS OWN verified successes only; cross-agent spend is
  never summed. Agents that cannot report a figure leave it absent —
  "unknown" is never written as zero.

## Findings

1. **rapid with grok-build-0.1: 24–25 of 40 (60–63%)** across credential-clean
   runs — real model non-determinism between identical runs. Failure clusters:
   the `recovery` pipelines and `workflow` tasks (both need a shell call that
   acceptEdits denies), three `tests` tasks, and three `multifile` tasks.
2. **Grok CLI with `--always-approve`: 40/40, three times** (including the
   definitive same-window run). Its native auto-approval covers shell, which
   the workflow and recovery tasks need; rapid's acceptEdits denies shell —
   in the definitive run 9 of rapid's 16 non-passes were `shell_exec`
   denials. This is a **configuration asymmetry**, not evidence of a model
   or harness gap: the comparable rapid configuration (shell approved) was
   not available because rapid's approval ladder treats shell as a distinct
   grant.
3. **Model attribution of earlier runs (superseded claim).** Earlier text
   said both agents drove "the same model family (grok-build-0.1)". The
   probes above show grok CLI 1.0.30 actually drove grok-4.6 while rapid
   drove grok-build-0.1 — so the earlier 24–25/40 vs 40/40 deltas mix a
   model-version difference with the approval asymmetry and support no
   model-quality conclusion in either direction.
4. **Anthropic adapter has no streaming yet** (documented); the OpenAI-
   compatible path streams deltas live via the incremental SSE transport.
   End-to-end proof post parser-fix: `rapid exec` against the live x.ai
   endpoint printed tokens to stdout in 3 separate reads before the final
   answer (probe verdict `PROGRESSIVE`, 22 s wall); the TUI reducer replays
   coalesced `model.stream_delta` ledger events without blocking
   (`state.rs` replay test). `rapid exec` and interactive turns attach the
   same delta sink in production paths.
