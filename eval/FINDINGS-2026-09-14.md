## Findings

1. **rapid with grok-build-0.1: 17–25 of 40 (43–63%)** across two runs — real
   model non-determinism between identical runs. Failure clusters: the
   `recovery` pipelines (the model does not reliably repair `pipeline.py`'s
   missing `os.makedirs`), three `tests` tasks, and the `workflow` tasks
   (which require the agent to run `rapid playbook-compile` — a shell call
   that acceptEdits denies).
2. **Grok CLI with `--always-approve`: 40/40, twice.** Its native
   auto-approval covers shell, which the workflow and recovery tasks need;
   rapid's acceptEdits denies shell. This is a **configuration asymmetry**, not
   evidence of a model or harness gap: the comparable rapid configuration
   (shell approved) was not available because rapid's approval ladder treats
   shell as a distinct grant.
3. **Both agents drive the same model family** (grok-build-0.1 via x.ai), so
   the delta is harness + approval configuration, not the model. The runs
   happened in different windows (rapid's OIDC token expired mid-run in one)
   and are reported separately rather than head-to-head.
4. **Anthropic adapter has no streaming yet** (documented); the OpenAI-
   compatible path streams deltas live via the incremental SSE transport.

## What would make the comparison exact

- Grant `shell_exec` for rapid's live runs (one `rapid permissions allow
  shell_exec` per scratch repo, or run with `bypassPermissions`) so both
  agents have the same tool surface.
- A static `XAI_API_KEY` (see `docs/credentials-request.md`) — the grok CLI's
  OIDC token rotates, which expired rapid's copy mid-run.
- Qwen Code: its free tier was discontinued 2026-04-15; a Coding Plan key is
  required for its headless mode.
